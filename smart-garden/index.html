Smart Garden

A connected planter that makes plant care visible. An ESP32 senses soil moisture and human presence, translating them into ambient light across the frame and soil bed, with live control through a cloud dashboard.

ROLE
Concept, enclosure fabrication, firmware, dashboard
STACK
Arduino IoT Cloud · C++ · ESP32 (M5Stack Core Ink)
HARDWARE
PIR motion · EARTH soil moisture · digital RGB LED strip
YEAR
2022 · Academic project
01

Problem

Soil moisture is difficult to judge at a glance. Digital sensors can expose that information, but numerical readings still require someone to actively check a screen.

DESIGN INTENTION
Make the planter itself the interface.

Plant state should be readable at a glance through ambient physical feedback, without requiring a separate screen check. The lighting activates when someone approaches, making the system responsive to both the plant and the person.

02

Process & iterations

Built end-to-end over one term: component selection, enclosure fabrication, firmware, and the control dashboard.

2.1Hardware

M5Stack Core Ink
ESP32-based main controller connecting sensor inputs, cloud variables, and lighting outputs.
EARTH moisture sensor
Measures moisture in the soil bed and provides the primary environmental input for moisture-state feedback.
PIR motion sensor
Detects movement near the planter and triggers presence-aware frame lighting.
Digital RGB LED strip
Provides programmable visual feedback through the frame and soil-line lighting.

2.2Physical fabrication

The frame was fabricated from MDF using a laser cutter and band saw, with a milled channel in the top rail to integrate the LED strip. An acrylic front exposes the soil bed, allowing the embedded lighting feedback to remain visible.

2.3From hard-coded behavior to live control

HARD-CODED FIRMWARE→CLOUD VARIABLES→LIVE TUNING

Thresholds and lighting values initially lived in the firmware, so adjustments required re-flashing the board. Moving lighting controls to Arduino IoT Cloud enabled live adjustment of color, hue, and saturation through the dashboard while sensor values could be monitored remotely. Tuning went from a compile cycle to a slider.

Arduino IoT Cloud — main dashboard and device registration.
03

Final design — three behaviors

3.1

Presence lighting

When someone approaches the planter, the PIR sensor detects movement and activates the frame lighting. This allows the physical interface to respond to a person’s presence rather than remaining continuously active.

INPUT
Person approaches
SYSTEM
PIR detects presence
FEEDBACK
Frame lighting responds
3.2

Custom lighting

Lighting controls are connected to cloud variables through Arduino IoT Cloud. Adjusting them on the dashboard updates the physical frame lighting in real time, allowing color and lighting states to be tuned without modifying the firmware.

INPUT
Dashboard control
SYSTEM
Cloud variable syncs
FEEDBACK
Physical lighting changes
3.3

Moisture feedback

LEDs at the soil line translate the moisture reading into a simple physical state: red for dry and blue for sufficient moisture. The exact sensor value remains available on the dashboard, while the ambient lighting makes the overall state visible at a glance.

INPUT
Soil moisture reading
SYSTEM
ESP32 evaluates state
FEEDBACK
Soil LEDs show condition

04

Learnings

4.1

Ambient feedback reduces screen dependency

Encoding plant state directly into the object made the system understandable without requiring a separate screen check. The planter itself became part of the interface.

4.2

Live variables change how you design

Once thresholds and colors became cloud variables, tuning became a design activity instead of a firmware chore.

4.3

Fabrication is interface work

The milled LED channel and the acrylic soil window aren't cosmetic — they are what make the feedback legible.
